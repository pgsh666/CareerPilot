# 出题与评测依据

更新日期：2026-10-28。

本文说明 CareerPilot 如何依据材料规划面试题、约束主问和追问、校验生成结果，以及如何依据实际作答评价。适用的自然对话策略为 `natural-jd-v2`，对应评分版本为 `careerpilot-rubric-v1-interview-v2`；基础分档规则为 `careerpilot-rubric-v1`。每场训练保存自己的材料和规则快照，历史结果按原版本解释。

出题、追问及复练变式由应用配置的 `deepseek-flash` 非思考模式生成，本地规则负责题位规划、输出校验和确定性计分。整场主问在一次生成任务中给出，追问随真实作答逐次决定，不额外增加独立的规划或审题模型调用。

## 一、出题约束与依据

### 1. 材料依据与使用边界

| 依据 | 用于什么 | 使用边界 |
| --- | --- | --- |
| 本人确认的简历 | 了解教育与专业背景、个人技能、项目、实习、本人职责及已经陈述的结果 | 材料自述作为提问线索，不等于经过外部核验的事实；不编造未说明的经历或业绩 |
| 本人确认的岗位材料 | 选择岗位方向、职责、能力要求和工作情境 | 以明确写出的内容为依据；加分或优先项不能变成硬性条件 |
| 已明确启用的岗位推断 | 在用户接受的范围内补充岗位背景 | 未启用的推断不进入模型上下文；推断不能冒充公司已确认事实 |
| 当前题组的真实作答 | 决定是否追问、澄清什么以及专业深入程度 | 追问须引用本次回答中的原话，并结合本组已经问过、答过的内容 |
| 固定评分维度和分档 | 给题目安排适用的岗位专项及参考要点 | 模型只在固定规则内选择考点，不能临时改变维度、权重或档位含义 |

开始面试时保存材料版本快照，随后修改或重命名材料不会改变该场面试的依据。材料中的命令性文字只作为待分析内容，不得改变系统任务、权限或输出格式。

出题使用已确认字段构成的上下文，引用也在该快照中核对；不能因为原文件里存在某段文字，就声称模型已经使用或核实了未进入上下文的内容。

项目经历既可以用于了解背景、目标用户、使用场景、约束和本人职责，也可以用于询问某次具体行动或选择。背景缺失时先询问，不假定候选人已经做过相关工作，也不要求每场机械覆盖全部背景要素。

### 2. 主问题组成与岗位要求选择

| 主问题数量 | 背景题 | 经历行动题 | 岗位要求实践题 | 假设工作情境题 |
| --- | --- | --- | --- | --- |
| 3题 | 0 | 1 | 1 | 1 |
| 5题 | 1 | 1 | 2 | 1 |
| 8题 | 1 | 2 | 3 | 2 |

背景题侧重“这段经历要解决什么问题、你负责什么”；经历行动题侧重一次具体做法或选择。岗位要求实践题可以询问工具使用、个人实践、学习方法或实际工作能力，不把全部问题都绑定到简历项目。情境题须明确是假设，不能把设定说成候选人或公司已经发生的事情。

题位顺序在出题前由本地规则确定。没有项目或实习材料时，相应的背景、经历题位改为岗位实践题，不凭空增加经历。岗位材料简略时，同一真实要求可以从不同侧面提问，问题仍须有所区别。

岗位要求实践题预先绑定具体的要求编号及原文。选取优先级为：明确必备项、已识别的AI工具使用要求、其他明确要求或职责、优先或加分项。同一优先级沿材料提取顺序安排。有限题数不保证逐项覆盖整份岗位材料；本场没有问到的要求，不能成为报告中的隐含扣分项。

当分配的要求涉及AI工具使用时，实际题干须明确问到AI工具或其中一个示例工具，不能只在隐藏的引用中体现。ChatGPT、Claude、Cursor等名称作为示例，不要求全部用过；关注一次具体使用、实际做法及对结果的判断。

### 3. 面试官口吻与专业深度

主问、追问和复练变式使用目标岗位面试官的直接对话口吻。可以用“我们要求”“我们希望”“这个岗位需要”引入，也可以直接提问，不必每题重复宣读岗位要求。“我们”代指本次模拟的招聘方，不能借此新增公司内部情况、产品现状或任职条件。

| 旁白式转述 | 面试官口吻示例 |
| --- | --- |
| JD要求具备基本AI使用经验，请谈一次工具使用。 | 我们要求具备基本的AI使用经验，能分享一次用AI工具完成任务的经历吗？ |
| 根据岗位描述，你是否会做需求分析？ | 能讲一次你梳理需求并决定先做什么的经历吗？ |
| JD要求能评估AI方案，请说说你的方法。 | 如果要判断一个AI功能是否值得落地，你会先验证什么？ |

示例用于说明表达方式，具体考点仍由本场材料与题位确定。优先项、加分项保持原有强度，不因换成面试官口吻而升级为必备要求。

主问先聊经历、实际做法或一个简短工作情境，一次只问一个核心问题，不堆叠术语、罗列子问题或要求背诵定义。正式主问最多120个字符。主问仍须给适用岗位能力提供作答机会，不能把全部专项考察推迟到可选追问中。

专业深入通过承接回答的追问逐步增加：先澄清具体行动，再视实际回答询问理由、验证方法或一个相关原理。深度结合岗位和本人作答调整。候选人没有相关经历时可如实说明，也可讨论假设方案；不要求编造经历、大型生产系统或量化成果。

### 4. 考点、参考要点与追问

1. 每个主问题题组包含三项通用维度，并按题意加入0—2项岗位专项；纯背景或职责题可以只评通用维度。整场主问须覆盖三项岗位专项。
2. 模型生成题目时同时提出该题的专项维度和1—3条参考要点。通过检查后，在展示与作答前锁定题目、维度及要点。
3. 参考要点只覆盖实际询问的内容，不暗藏未提问的原理、量化指标或完整方案；它不是唯一逐字标准答案，有依据的不同解法也可以成立。
4. 每个主问题最多追问两次。回答充分可以直接进入下一题，不为凑次数机械追问，也不提前生成整套固定追问。
5. 追问须引用当前回答的真实短句，结合本组历史避免重复。追问继续使用本组既定维度，并在展示前锁定自己的补充要点，不事后扩展评分范围。
6. 正式追问最多120个字符。决定结束题组时，不得夹带追问文本、回答引文或追问参考要点。
7. 复练先围绕原题改进，再生成考察同能力的新情境；变式不能只替换名字、数字或引导语。变式沿用自然对话要求，其题干结构上限为1500个字符，不复用正式主问、追问的120字符硬上限。

### 5. 系统校验与表达要求的区别

系统检查结构和可核对的关联；自然程度、专业适配和“是否真正只问一个核心问题”还需要结合内容判断。

| 检查项 | 系统处理 |
| --- | --- |
| 返回完整性与结构 | 模型须完整返回JSON，字段、类型及枚举符合对应结构，不能增加未允许字段 |
| 主问题数量与文本重复 | 数量须等于选择的3／5／8题；完全相同的题干不能重复计题 |
| 题位匹配 | 每题类别须符合预先锁定的顺序，岗位实践题须对应分配的要求编号 |
| 材料引用 | 引用须能在对应材料中逐字找到；经历题须有简历依据，岗位实践及情境题须有岗位依据 |
| 岗位考点关联 | 实际题干、分配要求和引用须有可核对的具体考察词；不能只填写隐藏标签或引用一段无关要求 |
| AI工具实践 | 分配到工具使用要求时，实际题干须体现相应工具实践，不以空泛的“能力”“经验”冒充覆盖 |
| 评分专项 | 每题只能选择该方向允许的专项，不能重复；整场主问覆盖三项专项 |
| 主问参考要点 | 至少1条、最多3条，不能用空白内容占位；参考要点与维度在作答前固定 |
| 追问依据及次数 | 当前回答中的真实引文、非空追问、最多两次追问；结束题组与继续追问使用不同的输出约束 |
| 正式题干长度 | 主问与追问最多120个字符；不是按说话时长计算 |

以下属于生成与表达要求，不以简单格式特征直接拒绝整套题：面试官口吻、一个核心问题、避免术语堆叠、专业深度逐步增加、避免语义上的重复。题号、列表符号或多个问号本身不构成整场失败理由。常见的“JD要求”“根据岗位描述”等转述前缀会做本地措辞调整，页面与语音使用同一处理；这种调整不改材料引文、作答、实质考点或历史评分结果。

### 6. 关键词匹配与自然表达

内部的 `requirement_focus` 用于标记本题实际考察的具体要点，推荐填写“需求分析”“Cursor”等一个关键词或短语。

系统不会把“需求分析／PRD撰写／项目推动”去掉分隔符后，要求整串标签连续出现在题干中。它会拆分复合标签，优先核对实际问到且有原文依据的要点；较长标签不准确时，可在同一分配要求内寻找题干与引用共同支持的具体词，并只纠正内部标签。

自然语序和有限修饰可以兼容，例如“PRD撰写”与“如何撰写PRD”、“新产品”与“新的AI产品”。普通能力、经验等空泛词，以及从英文工具名中截出的无意义字母片段，不能单独充当可靠的考点依据。

这仍是有范围的文字关联检查，不是完整的语义理解或无限制同义词匹配。它不能证明每道题都专业、自然，也不能替代对题目质量的实际评估。

### 7. 失败、缓存与费用

生成中重复点击或刷新读取已有任务，不自动追加付费调用。请求未完整返回、结构不合格、引用不实、岗位关联不足或评分覆盖不全时，任务显示失败及相应诊断；不拿模板题冒充成功。

模型已经处理并返回的请求，即使随后被校验拒绝，也按取得的用量记录费用。费用或完成状态不明时先核实，不立即重复调用。

用户手动重试时，优先按原快照离线复核本人私有缓存中的结构化结果。通过检查可直接恢复，不增加调用、尝试次数或费用；缓存不可用或仍不符合规则时，才在预算允许的情况下进行新的生成。不是每一种失败都有可恢复缓存，历史失败和费用记录也不会因恢复而抹除。

### 8. 出题与评价的衔接

出题决定本题提供什么作答机会，并在作答前锁定考点与要点；评价依据实际问到和答出的内容匹配固定分档。模型不能在看完回答后新增必答考点，不能把尚未发生的追问、没有询问的专业原理或整份岗位材料当成额外扣分清单。

同一主问和追问属于一个题组，补充回答可以完善判断，关键矛盾须指出；追问次数、答案长短和术语数量不增加分值权重。具体评分、证据覆盖及综合分门槛如下。

## 二、评测依据

CareerPilot 根据实际问答、题目预设考点与固定分档生成反馈。模型负责提出维度档位、理由及原话证据，服务端负责校验并计算分数、完成率与证据覆盖率。逐题参考要点在题目展示前锁定，不要求逐字复述，也允许有依据的不同解法。

### 维度与权重

每个方向均使用三项通用维度：回答相关性15%、逻辑表达10%、回答依据与职责说明15%；三项岗位专项各20%，合计100%。下文覆盖七个评分方向。完整规则快照位于 `backend/app/scoring_rules.json`。

### 档位和无依据状态

| 档位 | 百分制映射 | 含义 |
| --- | --- | --- |
| 0 | 0 | 有明确错误且未体现有效要素，需有可评价依据 |
| 1 | 25 | 少量要素，关键欠缺 |
| 2 | 50 | 基本正确，有重要缺项 |
| 3 | 75 | 准确且较完整 |
| 4 | 100 | 表现充分，按题目需要解释边界、验证或取舍 |
| N/A | 不计分 | 无可评分依据，不等于0分 |

完全未答、直接跳过、只说不会或没做过且没有实质分析时，相关维度为N/A。存在假设分析则按实际内容评价；泛泛、遗漏或错误等已有表现仍需给出相应档位，不能用N/A排除低分。

仅评价实际已问内容。尚未发生的追问、未询问的深层原理不能成为隐含扣分项。简历自述不等于经过外部核验的真实业绩，反馈引用必须来自对应题组的本人回答。

各维度独立判断。专业结论有误时，在适用的岗位专项中评价；不能仅因专项错误就连带降低回答相关性或逻辑表达。通用维度确有偏题、矛盾或依据欠缺时，再按该维度的实际表现给档。回答长短、术语数量、是否使用特定框架或工具，不直接决定档位。

### 题组、汇总与覆盖

1. 一道主问题与其最多两次追问构成一个题组，结合全组实际回答，每个适用维度只评价一次；追问次数和回答长度不增加权重。
2. 各题组预先分配考察维度。每组包含三项通用维度，按题意加入0—2项岗位专项；整场主问需覆盖三项专项。
3. 同一维度的有效题组先映射到百分制，再等权平均。N/A不补零，也不重新分配六维权重；有效0分参与计算。
4. 每维覆盖率＝有评分依据的题组数／预定考察该维度的题组数；整体覆盖率按六维固定权重加权。跳过、无依据及提前结束未答组保留在预定分母中。
5. 答题完成率＝提交过非空回答的不同题组数／原定题组数。只说不会可以算已提交，但不因此算有评分依据；追问不额外计组。

显示综合分须同时满足：评价已完成、至少3个不同题组有评分依据、六维各有至少一个有效分、整体证据覆盖率不低于80%。门槛使用未四舍五入的值。不满足时展示已有维度分、反馈和缺少综合分的原因，不补造总分。

成功报告固定保存，失败重试使用原材料、回答、考点及评分版本；旧训练不跨版本重评。历史趋势只比较同岗位方向、同JD版本、同评分版本且正常完整结束、总分有效的面试。复练不产生独立综合分排名，也不混入完整面试趋势。

### 通用维度分档

| 档位 | 回答相关性（15%） | 逻辑表达（10%） | 回答依据与职责说明（15%） |
| --- | --- | --- | --- |
| 0 | 明显误解题意，或有作答但完全偏离所问重点 | 关键表述前后矛盾或因果混乱，无法形成可理解的思路 | 所述依据与结论明显冲突，或本人职责表述自相矛盾 |
| 1 | 只触及少量相关内容，未回应核心问题 | 内容零散，步骤或观点之间缺少联系，主要思路难以还原 | 仅有泛泛结论或少量事实，关键依据或本人作用不清 |
| 2 | 基本回应核心问题，但遗漏重要子问题或必要信息 | 主线基本可理解，但关键步骤、因果或衔接仍不清楚 | 有具体案例或推理，能说明基本职责或验证思路，但缺少关键细节 |
| 3 | 回应主要要求，内容与题意一致，没有明显遗漏 | 过程或推理清楚，步骤与结论连贯、自洽 | 事实或推理与结论对应；经历题能说明本人职责，假设题能说明依据和验证方法 |
| 4 | 完整回应本题要求，重点明确，信息取舍恰当 | 层次清楚且组织紧凑，关键推理和条件明确，便于核对理解 | 依据具体、可核查，能说明其适用条件或局限，并区分事实与假设、个人与团队贡献 |

逻辑表达按题型评价，不机械套用项目叙事模板；经历题说明本人职责，假设题说明依据与验证方式，没有量化成果时不要求编造。

### 后端开发专项分档

| 档位 | 接口与数据设计（20%） | 可靠性与异常处理（20%） | 性能与技术取舍（20%） |
| --- | --- | --- | --- |
| 0 | 核心接口契约或数据关系明显错误，方案无法满足题目明确要求 | 对题目已明确的权限、异常或一致性要求给出明显错误的处理，不能保障所需行为 | 错误判断关键因果，或提出与题目约束明显冲突的优化方案 |
| 1 | 只罗列接口、字段或技术名，缺少输入输出或数据关系说明 | 只泛称加校验、重试等，未说明针对的风险、处理时机或失败路径 | 只罗列缓存、并发等手段，未联系本题的负载或瓶颈 |

### 解释边界

自动结构检查、引用检查和聚合算法不能代替专业效果评估。分档理由应能从问题与实际回答追溯；发现跨题引用、虚构原话、事实与假设混淆或明显专业错误时，应保留相关题目、回答和报告记录进行复核。分数用于练习反馈，不作为录用判断或经历真实性证明。

## 三、报告生成标准

### 1. 触发、来源与呈现

正式面试正常完成或明确提前结束后，依据已保存的问题、实际提交文字、材料快照、锁定考点和该场评分版本生成报告。只评价实际问到、答出的内容；不使用未来追问、参考答案或材料自述补写作答。复练阶段反馈使用自己的实际提交，不覆盖来源面试报告。

“报告概览”“逐题回顾”“维度评分”读取同一场训练的报告和问答。切换页签、刷新及重复打开成功报告不会分别触发模型调用。逐题回顾保留原问、追问和原答；概览突出主要不足、原话依据、改进步骤与对应复练入口。

模型提出概览、反馈、改进项、维度档位及理由，服务端核对来源、归组并确定性计算分数、完成率和覆盖率。模型不负责自由生成最终综合分，也不能改变固定权重、门槛或分档。

### 2. 按题组组织完整上下文

一道主问题及其实际发生的最多两次追问属于一个题组。报告输入按有非空且未跳过作答的主问题题组组织；每组包含本组实际问答、各次参考要点和既定维度，并提供准确的题组ID列表。原定未答、跳过或提前结束未到的题组仍保留在服务端完成率及证据覆盖率分母中。

例如，5道主问题中发生6次追问，且5组均有作答：虽然可能共有11轮回答，最终仍为5组反馈和5组评分。追问补充可以完善同组判断，不增加该组权重，不把11轮对话当成11道独立主问题。

### 3. 引用原文片段，不让模型重抄证据

服务端按顺序将每份实际回答划分为最多40个字符的连续原文片段，并分配片段编号。分片完整保留原文、空格、数字和英文，不删减作答；模型结合全组完整内容判断后，选择已有的 `evidence_ref`。服务端据该编号回填原话、回答ID及具体题目ID。

片段编号是证据定位方式，不是新的评分维度。模型不能选择不存在的编号、跨题组引用、把改进建议写成用户原话，或用概括转述代替原文。改进项由实际回答定位到对应主问或追问，并据此建立复练来源。新报告引用的是最终保存的回答文字；语音误识别不会被模型悄悄改成另一份证据。

### 4. 简洁输出目标与兼容边界

| 内容 | 发给模型的生成目标 |
| --- | --- |
| 概览 | 最多180个字符 |
| 题组反馈与评分行 | 各恰好覆盖本场实际有作答的主问题题组 |
| 每组已体现、待补充 | 各最多1项，须关联本组真实回答 |
| 每维理由与证据 | 理由最多40个字符，最多1条原话证据 |
| 单条证据评论 | 最多80个字符 |
| 单条优先改进建议 | 最多100个字符，并可追溯到原答 |

这些是新任务的模型输出约束，用于控制返回长度和重复信息；兼容解析旧结果仍沿用较宽的字段边界，不仅因旧文字略长就额外拒绝整份报告。返回仍须符合实际解析结构的必填字段、类型、枚举和数量上限。完整问答由原记录保存，不依靠180字概览代替。

### 5. 必须通过的校验与安全归组

1. 返回完整且符合对应结构，所有题组、回答、证据来源和维度可定位；最终恰好覆盖本场有作答的主问题题组。
2. 评分仅包含题组预定适用维度，档位为0—4或符合规则的N/A；逐维证据与理由满足来源和适用范围要求。
3. 每条原话可逐字定位到本组实际提交。新的片段引用按服务端原文回填；读取旧结果时，原有逐字引用仍要校验，不能近似匹配或修改原话凑成通过。
4. 先核对所有原始反馈和评分，再将可确认的追问ID映射到主问题，合并反馈，去除完全相同的重复评分。旧式评分兼容读取最多24行（8道主问各最多3轮），最终仍每个主问题题组只保留一套评分。
5. 同组重复评分若档位、理由或证据不同，不自动平均、删去冲突项或改成N/A；无法安全归组时标记失败。
6. 旧改进项的回答ID和逐字原话正确，但题目ID指向同组另一轮时，可以由真实回答关系修正题目ID；不跨题组改绑。不存在的片段、跨组来源及互相冲突的显式来源字段仍拒绝采用。

格式和关联检查通过不等于专业判断已被证明正确。明显专业错误、无依据扣分、把假设当事实等仍须结合原问原答复核。

### 6. 生成状态、失败重试与费用

| 状态或操作 | 系统行为 |
| --- | --- |
| 排队或生成中 | 显示等待，重复点击和刷新读取原任务，不另开付费请求 |
| 结构或证据校验失败 | 显示失败与可用诊断，保留已提交问答；不填零分或模板报告 |
| 用户手动重试 | 沿用原材料、问题、回答、要点及评分版本，先核对本人私有的已付费结果 |
| 缓存可安全恢复 | 本地完成全部校验并保存，不新增模型调用、费用或尝试次数 |
| 无可恢复缓存 | 仅在允许重试、费用状态明确且预算足够时，发起新调用并记录实际费用 |
| 成功但无综合分 | 仍为有效报告，展示已有反馈、维度分和缺少总分的原因 |
| 已成功 | 一场保留一份成功结果，刷新、重进及重复点击不再生成 |

报告手动重试可按同一任务核对最近20次已记录失败调用的私有缓存，采用通过完整校验的结果；不是每种失败都存在可恢复缓存。原始失败结果及费用台账保留，恢复不会抹掉已发生的收费。未知完成状态或费用先核实，不连续自动重试。

主动退出、授权失效或停用后，旧登录不能继续提交或推进训练。已经发出的调用可以私有收尾并记录费用，账号可用且本人重新登录、主动继续后再按已有状态应用。永久注销不恢复账号。成功报告及历史训练不因文档更新或模型参数变化而重写。

综合分门槛、N/A与覆盖率见上文评分标准。覆盖不足与生成失败分别处理，不通过补零或放宽证据规则制造“有分报告”。

## 四、语音作答与转写标准

### 1. 本机识别与术语提示

浏览器录音由本机 Whisper small 离线转写，问题播报使用 Windows 中文 SAPI。新录音在首次保存转写前用本地 OpenCC 统一转为简体中文；繁简转换不负责猜测英文拼写、改写数字或补全回答。识别使用中文初始语言及中英混说设置、5束搜索和静音检测，不增加云端语音费用。

英文术语动态从当前题目、本场已确认岗位的要求/职责/方向，以及简历的个人技能/项目/实习字段提取。当前题目优先，每次最多32项，总长度最多512个字符；去重并过滤常见连接词、邮箱和网址。姓名、联系方式、未启用推断、参考要点和标准答案不作为术语提示来源。

ChatGPT、Claude Code、Cursor、RAG、F1、Python、MySQL等均可在实际材料出现时成为候选词，不是必须在所有录音中加入的固定词库；提示也不保证特定词一定识别正确。不用评分要点或同音词替换补写用户没有说出的内容。

### 2. 作答与恢复

- 单次录音最长3分钟、完整音频不超过10MB；服务端收到完整音频后的转写处理上限120秒，达录音时限停止并转写。
- 正式面试转写只读，成功后自动提交；复练可编辑转写并手动提交。无声、损坏、超限及空白结果不提交空答案。
- 首次故障后，有合规音频时最多手动重试一次，也可直接重录或使用故障键盘入口。已转写成功但提交失败时，仅重试原文字提交，先查询不明状态，不覆盖已接受答案。
- 浏览器原始录音只在当前作答页内存暂存，成功、放弃或离开后释放；服务端每次处理结束清理临时音频。刷新后未完成的录音需要重新录制。
- 已提交历史回答、原有证据及成功报告不回写。报告引用实际保存的转写；复练分别保留原始转写及最终提交文字。

不同口音、噪声、中英切换和专有名词仍可能误识别；本机合成语音回环只能验证固定样例，不能替代真人麦克风验收，也不能将词表辅助描述为英语识别完全通过。

截至2026-10-28，AI产品经理方向102项本机功能人工验收均已通过，包含真人语音与专业词识别。该结论限于此次方向、环境及功能清单，不外推为所有英文词、口音、噪声或七方向专业评分均已验证。
